# 服务端 UI 栈：shadcn/ui Nova + 受控依赖

Status: accepted
Date: 2026-10-24

## 背景

前几轮静态 demo 各自手写 CSS，结果是「海报感」：排版很重、应用骨架很轻，表格、筛选、分栏、
弹层都不像真实产品。需要一套成熟、可复制、可长期维护的组件来源，并且严格限制同类依赖。

## 决定

- **风格**：shadcn/ui **Nova**（紧凑密度、减少内外边距），用于数据密集的控制台与目录。
- **组件来源**：shadcn 组件源码复制进 `service/src/components/ui`，按需修改；不引黑盒 UI
  框架，不用运行时主题包。
- **图标**：只用 Lucide（`lucide-react`）。不用 emoji、不手绘内联 SVG。
- **动画**：只用 Motion（`motion/react`），页面切换与列表入场各一处，不做满屏 hover 动效。
- **分栏**：`react-resizable-panels`（审核台、服务台）。
- **拖拽**：`dnd-kit`（截图排序、队列排序）。
- **客户端状态**：Zustand（安装弹层、筛选、截图顺序）。
- **样式**：Tailwind v4 + CSS 变量 token；14px 基准、8px 网格、无渐变。

## 依赖纪律

- 同一能力只保留一个库（图标、动画、分栏、拖拽、状态各一个）。
- 新增依赖必须先在 `knowledge/decisions/` 写「为什么是它、放弃了谁、什么条件下换」。
- 组件源码进仓，升级靠人工 diff；不跟随上游自动升级。

## 放弃的方案

- 三套 bespoke CSS demo：视觉各自成立，但无法拼成一个产品。
- Ant Design / MUI：组件黑盒、定制成本高，与 Nova 的密度不合。
- Redux / SWR：v1 的客户端状态与请求量不需要。
- 多图标集混用：风格不统一，包体也会膨胀。

## 代价与重开条件

- shadcn 组件要自己维护，Radix 升级要跟。
- Nova 密度需要逐页调间距，不能直接套默认示例。
- 若出现复杂数据网格（虚拟滚动、列固定），再评估 TanStack Table；届时写新 ADR。
