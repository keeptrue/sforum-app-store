# 安装门禁：页面决定「这一版还能不能装」

Status: accepted
Date: 2026-10-26

## 背景

目录页的安装按钮此前只看三件事：有没有可安装版本、选了哪个平台、安装是否正在进行。
它**不看这台宿主机上已经装了什么版本**。

core 侧也不会替我们拦：`InstallOrUpgradeArchive` 只要扩展 id 相同就把新包当候选暂存
（`isUpgrade = true`），没有降级判定，也没有「同版本」判定。于是两个动作在真实宿主里都是
一次点击就能发生的：

- **同版本重装**：重新下载同一份 ZIP、重新弹一次 `super_admin` 精确制品信任确认，结论是
  候选制品被同一份字节覆盖 —— 纯噪音。
- **降级**：把 `1.5.0` 装到已跑 `2.0.0` 的宿主上。core 会把 `1.5.0` 暂存为候选，启用后
  迁移是**不可逆**的（新版本的列/表已经写过），这不是一个「点错了再点回来」的操作。

## 决定

1. **关系由后端算，页面只做展示。** 插件后端（`mapping.go` 的 `installedRelation`）对每个
   release 给出 `newer | same | older | unknown`，用与 `updateAvailable` **同一个**
   Masterminds semver 实现。理由：页面是零依赖手写 ESM，两套版本比较一定漂移。
   宿主清单读不到时不写这个键 —— 没有已装版本就没有「相对谁」的关系。
2. **门禁规则**：未安装 → 可装；`newer` → 可装，按钮文案变「更新到 vX」；`same` /
   `older` / `unknown` → 阻断。
   `unknown`（任一端口不是 semver，例如 dev 构建从 git tag 得来的版本）**也阻断**：此时页面
   给不出结论，宁可让操作者去 core 手动处理，也不要替他猜「大概能装」。
3. **阻断时不留空位，也不留一个能点的按钮。** 同一槽位保留一枚中性化的禁用主按钮
   （`已安装 vX`），原因写在状态位里。理由：把按钮整块藏掉会让右下角出现一个洞，读起来像
   页面坏了。
4. **缺关系时退回「可装」。** 后端在清单可用时一定会给关系，缺了就只可能是页面比自己的后端
   新（或有人手改了 bundle）。这时退回改动前的行为，而不是把所有升级都锁死。
5. **版本下拉自带结论。** 选项文案是 `1.4.2 · 稳定版 · 可升级 / 已安装 / 低于已安装`，
   选中之前就能看到关系，不用先点一次才知道被拦。

## 修订（2026-10-26，操作者决定）

初版在阻断态同时给了「去 core 卸载」快捷入口（`bridge.navigate` 到
`/extensions/plugins` 或 `/extensions/themes`）。**已移除。**

理由：卸载是破坏性动作，入口就在「浏览目录」的手边，误点的代价远大于少走两步；而且真正要
卸载的人本来就要进 core 的扩展页确认状态（是否启用、是否有 staged 候选）。现在阻断态只有
一枚禁用的 `已安装 vX` 与一句原因，页面不再提供任何写操作。

## 放弃的方案

- **隐藏安装按钮**（最初的设想）：见上，空位会被误读；而且没有给出下一步。
- **「去 core 卸载」快捷按钮**：见「修订」——破坏性动作不该放在目录手势路径上。
- **让 core 拒绝降级**：那是跨仓的语义变更（`InstallOrUpgradeArchive` 要引入 downgrade 概念、
  迁移可逆性评估、审计事件），本轮不该由一个 UI 诉求推动；页面级门禁先解决「误点」。
- **同版本允许重装**：core 对同一 digest 是幂等的，但触发的是下载 + 一次信任确认，
  对「这次点击想达成什么」没有帮助。
- **按 `latestVersion` 而不是选中版本判关系**：下拉允许选历史版本，只看 latest 会放过
  一次真实的降级。

## 代价与重开条件

- **这是 UX 守卫，不是安全边界。** 粘贴签名链接到 core 的安装页仍然能装任意同 id 包；
  本门禁只覆盖「从商城目录直接点」这条路径。
- **已暂存候选不可见。** 宿主清单（`extensions.active_version_id`）只报**活动**版本；刚把
  `2.0.0` 暂存、还没启用时，页面仍显示「更新到 v2.0.0」。重复暂存同一候选是幂等的
  （同一 digest），所以不会产生错误状态，只是提示不够精确。要修需要在宿主清单里加 staged
  字段（跨仓）。
- **`unknown` 会挡住 dev 构建上的自装**：本地把插件自己装进本机论坛时版本号常常是
  `dev-xxxxx`，此时商城页会显示「无法比较版本」。这是刻意的：这种场景应当走 dev 外源
  watcher（零命令），而不是从商城下载自己。
- 重开条件：宿主清单开始报 staged 版本，或 core 自己引入 downgrade 语义。
