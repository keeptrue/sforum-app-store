# 商城在 SForum 之外

Status: accepted
Date: 2026-10-24

## 背景

商城要服务多个 SForum 站点，处理不可信开发者输入、GitHub 出站流量与签名分发。把它塞进某个
论坛实例，会让目录可用性、权限面与发布节奏被单站点绑死；论坛故障会直接打掉目录。

## 决定

- 一个仓库两个产物：独立服务端 `service/` + SForum 扩展 `plugin/`。
- 唯一跨产物面：`contracts/store-api.yaml`（OpenAPI）与 core 的
  `sforum.extensions.install.*` 命令。
- 商城不写论坛数据库、不调论坛内部接口；登录只经 SForum OAuth2 提供方。

## 放弃的方案

- **塞进论坛插件**：目录与论坛同生命周期，升级要跟论坛版本走；不可信开发者输入进入论坛进程。
- **多租户共享一个 GitHub App**：官方成为所有自部署实例私有仓库的中间人，一处私钥泄露即
  全租户失守。

## 代价与重开条件

- 两套部署、跨仓契约、版本漂移；用契约生成 + CI 漂移检查兜。
- 自部署运维要自己注册 GitHub App 与 OAuth client。
- 若未来出现「论坛内嵌只读目录」的强需求，可加只读镜像，但不改变服务端权威。
