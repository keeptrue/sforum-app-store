# 下载分发：公开仓库可切 302，私有仓库永远走代理

Status: accepted
Date: 2026-10-25

## 背景

D4 把「所有下载走商城签名短链代理」定成刻意选择：一条信任链、藏起上游地址、支持私有仓库、
yank 立刻 410。代价写在同一份计划里——带宽由商城自己出，CDN/直链留到后续。

这个代价在按量计费的环境里变成了真金白银：一个 20 MB 的包，一万次安装就是 200 GB 出网。
商城的部署形态是单台 VPS，出网要么吃配额、要么按 GB 计费。

关键观察：`/api/v1/download/{token}` 这条管道里，商城真正不可替代的只有两件事——**验签并
复核数据库**，以及**决定这一跳允不允许**。搬字节不是其中之一。GitHub 在应答
`GET /repos/{o}/{r}/releases/assets/{id}` 时本来就会回 `302` 到一个短时签名对象地址，那张
地址就是给客户端用的凭据（`lib/github/client.ts` 的注释早就写明：带 installation token 去取
那个地址既泄 token 也让签名失效）。

## 决定

新增 `STORE_DOWNLOAD_MODE=proxy | redirect`，默认 `proxy`（行为完全不变），启动时校验，非法值
直接失败而不是静默降级。

`redirect` 模式的行为：

- **仅对公开仓库生效。** 私有仓库的对象地址里带着仓库名、tag 与文件名，那是真敏感信息，继续
  走代理。
- 复核顺序不变：验签 → `download-ip` + `download-token` 双限流 → `resolveDownloadTarget` 五项。
  任何一项失败仍然是原来的 410/503，**不签发 302**。
- 通过后只做一件事：`GithubAppClient.assetRedirectUrl` 拿到 `Location`，以 `302` 交给客户端，
  并带 `Referrer-Policy: no-referrer`（token 在请求路径里，不能跟着跳转回到上游日志）。
- GitHub 若回 `200` 自己吐字节（API 文档明确两种形态都可能），没有地址可给，**回落代理**，
  不报错。
- 短链本身不变：`issueDownloadUrl` 仍然只发 `${publicUrl}/api/v1/download/{token}`，插件、
  宿主、前台一行都不用改。

## 放弃的方案

- **Cloudflare Worker 边缘代理。** 能同时保住「藏上游」和「可撤销」，但要引入第二个部署物，
  且源站看到的连接方变成 Cloudflare 出口 IP —— `download-ip` 桶会把所有人算成一个人，
  默认 `60/300` 立刻变成全站 429，必须先把 IP 归属搬到边缘。收益与 C 相同，成本高一档，
  留作「宿主不跟随跨域 302」时的替代。
- **R2/S3 镜像 + 预签名。** 出网同样为零、还多出 Range 与「上游挂掉也能装」，但它破「不存包体」
  （`2026-10-24-s2-github-and-zip.md` 已否决），且要付 yank 删对象、摘要巡检、保留策略。
- **不区分公开/私有的 302。** 省事，但把私有仓库的对象地址交出去，没理由。
- **把 installation token 下发给客户端。** 那是一个仓库范围的 bearer，比它要解决的问题危险得多。

## 代价与重开条件

- **已发出的 302 撤不回。** yank、下架、断开之后再请求同一条短链仍然 410（复核在签发这一跳），
  但**在 yank 之前已经拿到 Location 的那一次跳转**，会在上游签名到期前继续可用。窗口长度
  **实测为 1 小时**（2026-10-25：`GET /repos/{o}/{r}/releases/assets/{id}` 返回的签名地址里
  `skt`→`ske` 正好 60 分钟，`se` 与之相同），不是社区传闻的「分钟级」。同一地址还支持 Range
  （实测 `206` + 1024 字节），这是代理模式做不到的。回滚只需把分发形态改回 `proxy`，后台保存
  即生效，不用重启。
- **失去按次观测**：这批下载不再经过商城，`download-*` 桶只统计签发次数。
- **契约多出一个形态**：`/v1/download/{token}` 现在可能回 200 或 302，`contracts/store-api.yaml`
  已写明，调用方必须能跟随跨域 302。
- **一个未验证的 go/no-go**：SForum 的 `install-from-url` 是否跟随跳到第三方主机的 302。
  AGENTS 里「公网 HTTPS 跳转未验证」仍然成立；不跟随则该模式对插件安装无意义，转边缘代理。
- 私有仓库比例高时收益按比例下降；如果最终私有仓库变主流量，重新评估边缘代理。
